## Owner decisions carried over from episode 1 research

### Coriolis meters: mass or volumetric proving (decided 2026-09-25)
- **Finding:** [Coastal Flow, "Understanding Liquid Meter Provings and Proving Reports" (L. McCombs), p.1](https://coastalflow.com/wp-content/uploads/2021/07/Understanding-Liquid-Meter-Provings.pdf) says Coriolis meters are "the only meter that directly measures and produces a mass pulse output, or that is proved with the mass methodology". The demo data proves volumetrically (K in pls/m³).
- **Decision:** episode 2 must include a sentence saying that Coriolis meters can be proved by either the mass or the volumetric method, and that this series follows the volumetric method, as in the manual. The evidence is that the report carries CTL and CPL corrections.
- **Verified in episode 2 research:** [S. Baldwin (Unocal) & T. Gupta (Daniel Measurement & Control, Emerson), "API MPMS Chapter 5 Section 6 for Proving Coriolis Meters – An Overview", FLOMEKO 2004, p.437](https://www.imeko.org/publications/tc9-2004/IMEKO-TC9-2004-060.pdf): "The meter factor for a Coriolis meter could be either a Mass meter factor (MFm) or a Volume Meter factor (MFv), based on the measurement configuration selected." Coastal Flow p.2 adds that CTL and CPL "are typically not applied to mass proves", which supports the volumetric reading of the demo report.

## Conflicts — owner decisions (2026-09-25)
1. **Terminology vs. episode 1.** Episode 1's closing line says "المُرُورُ، وَالشَّوْطُ، وَقَابِلِيَّةُ التَّكْرَارِ" (pass = مرور, run = شوط). The episode 2 brief uses pass = شوط, run = جولة. Episode 2 follows the brief.
   **Decision:** the whole series uses الشوط = pass and الجولة = run (added to CLAUDE.md). Episode 1 is not changed now.
2. **10-run limit.** [H. James, NFOGM, "Liquid Meter Proving Techniques"](https://nfogm.no/wp-content/uploads/2014/07/Liquid-Meter-Proving-Techniques.pdf) lists "10 runs with 0.10% repeatability" as a "commonly accepted criterion"; the API 4.8 table (Lantzy, Coastal Flow, Buttler) gives 0.12 % for 10 runs. The episode shows only 3–6 runs, so it is not affected. **Decision:** accepted.
3. **Averaged passes and the API 4.8 table.** Our runs are each the average of 3 passes. Sources confirm API 4.8 allows averaging passes per run (Buttler, Lantzy) but we could not read whether API 4.8 gives a separate limit table for averaged-pass runs (the standard is paywalled). The narration applies the 0.05 % limit for 5 runs, as in the owner outline, and makes no claim about a separate table. **Decision:** accepted.
4. **Daniel prover repeatability 0.02 %.** The Daniel manual (§1.4) quotes "Repeatability 0.02% or better (water draw)"; this is the prover's own waterdraw performance, not the proving limit. Left out of the narration to avoid confusion. **Decision:** accepted.
