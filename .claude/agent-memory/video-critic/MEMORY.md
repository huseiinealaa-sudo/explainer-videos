# video-critic memory

Recurring faults in this repository. Each line: what it looks like · how to spot it · usual fix · first seen.
Look for every one of them in each preview. Keep this file under 150 lines; merge, don't repeat.

## Drawing and colour
- **Manim subclass default colours escape `VMobject.set_default(color=INK)`**: `Rectangle`/`Square` without `color=` get WHITE (invisible on the white board, only a PANEL_FILL smudge shows), `Circle` gets manim RED (reads as the alarm accent), `Polygon`/`Triangle` get manim BLUE #58C4DD (off-palette); `DashedVMobject(src, color=...)` ignores `color=` and copies `src`'s style, so a dashed WHITE outline is invisible **and cuts the black lines it crosses** · spot: a part with no outline, salmon-red small circles, light-cyan shapes, a short gap in a black line where nothing is visible · fix: pass `color=` (INK / GREY_INK / palette role) to every Rectangle, Circle, Polygon and to the *source* of a DashedVMobject; delete decorative shapes that are not named · first seen svp_winsfc_full seg 2.
- **Mechanism only pulsed, not moved**: the narration describes a motion or cause ("X cuts the beam of Y", "A pulls B", "moves with") but the frame only gets `Indicate`/`Flash` on a static `labeled_diagram` · spot: the same drawing, unchanged in every 3 s frame while such a sentence is spoken · fix: animate it (shift the linked VGroup, draw the beam/signal, flash the sensor), then return; root Quality standard: every mechanism is an animated drawing · first seen svp_winsfc_full seg 2. Worse form: nothing moves at all, only a label/arrow ("moves with the liquid", "pushes the piston ahead") · seen again prover_ep03_components seg 4 (return the part before later objects built at its rest coordinates are used).
- **Subject of the segment drawn tiny**: the part discussed for most of the segment sits in one or two cells while a part named once takes half the frame · spot: small parts (r < 0.1, < 0.6 units) under long narration · fix: enlarge those parts or zoom on them once the first callouts are done; `SyncedScene` is a plain Scene (no camera zoom), so use a scaled-copy inset (`VGroup(parts).copy().scale(2.5)`) in an empty region and fade it before that region is used · first seen svp_winsfc_full seg 2; again prover_ep03_components seg 4 (piston + poppet in part of C3, A2–B5 empty).
- **Part introduced in a later operating state**: a valve/piston first appears already open/moved (hole, offset), so the drawing contradicts the naming sentence ("inside the piston" while the open poppet sits outside it) and shows a state before it is explained · spot: compare the first frame of each new part with the words then · fix: introduce it at rest, animate into the state at the state's cue, keep the segment's end state · first seen prover_ep03_components seg 4.

- **Spoken motion animated to the value the tracker already has** (`lever.animate.set_value(0)` while lever is 0): the cue plays but nothing moves · spot: two identical frames across the cue of a motion verb · fix: put the part in the opposite state before the cue (end the previous segment there) · first seen pt_cal_ep02_pressure seg 4. Again ut_series_ep03 seg 4 ("we set the arc echo on 100 mm": the echo sits on 100 from the first frame, only a dashed line appears) → start the echo mis-set (e.g. 85) and slide it with a Range knob at the cue.
- **Before-state never visible**: a change animation ("wear moves the exit point") starts 0.1 s after the build of the part ends, so no frame shows the "before" and the change reads as nothing · spot: compute build end vs change cue from the code; frames before/after look the same · fix: leave a ghost (dashed GREY_INK copy of the old outline / old index mark / old beam) and an arrow between old and new, start the change at the effect's word · first seen ut_series_ep03 seg 1.
- **Angle probe drawn as a right triangle with the crystal on the vertical back face and the exit point at the toe** (`wedge_probe`): the beam leaves from the front corner, so the "exit point" is just the probe's front edge — contradicts why it must be found on the V1 arc and marked; wear drawn as the toe cut back · spot: any angle-probe sketch whose beam starts at a polygon vertex · fix: crystal on the slanted face, sole extending on both sides of the exit point, beam inside the wedge from crystal centre to the exit point (incident angle from Snell), `g.exit` unchanged · first seen ut_series_ep03 seg 1, 3, 4, review. Reversed form: wedge high at the back, slope falling toward the weld, `Probe` (face = bottom) `rotate(-0.9)` → the crystal faces down-*back* while the beam leaves forward from the sole; no ray inside the wedge, so "it refracts" shows no bend · spot: on the angle-probe frame, which side of the probe body is the thick crystal bar, and does the slope rise toward the beam direction? · fix: slope rising toward the weld, `rotate(+atan(h/w))`, incident dashed ray from the face centre to the exit point · ut_series_ep02 seg 3 (round 3).
- **Pulse-echo bounce counts one-way trips**: in a multiple-echo animation an echo is added each time the pulse reaches a face (back wall included), so 4 echoes after 2 round trips and the first echo appears while the pulse is moving away from the probe · fix: add an echo only when the pulse arrives back at the probe face (round trips) · first seen ut_series_ep03 seg 2.
- **Probe slide with the beam redrawn to the target**: `always_redraw(DashedLine(exit, hole.get_center()))` swings the beam angle as the probe moves, so the reflector is always hit and the echo maximum has no geometric reason · fix: fixed direction from the probe angle (`exit + d * L`), the beam passes beside the hole until the peak position · first seen ut_series_ep03 seg 4.
- **Stale `always_redraw` value on re-entry**: a redraw group removed by `clear()` and faded in again shows its old value (a readout 30.0 → jumps to 18.0) because updaters are suspended during FadeIn · fix: `for m in group: m.update()` before the FadeIn · first seen pt_cal_ep02_pressure seg 7. Variant: `redraw.animate.set_color(GOOD)` on an `always_redraw` is overwritten next frame (bar stays orange while "→ longer" is green) · fix: read the colour from a variable/tracker inside the lambda · pt_cal_ep05_verdict seg 5.

- **Arrow grown from a stub loses its tip**: `Arrow` created 0.1 long then `put_start_and_end_on(...)` to full length shows as a plain line (no head), so a force/direction reads as a bar · fix: build the final Arrow and `GrowArrow` it, or `always_redraw(lambda: Arrow(..., tip_length=0.25))` on a ValueTracker · first seen pt_cal_ep02_pressure seg 8.
- **Same action in two palette roles**: opening a valve drawn red (danger) in one segment and orange (moving part) in another · spot: compare colours of the same part/action across segments · fix: one role per action, from the project CLAUDE.md · first seen pt_cal_ep02_pressure seg 5 vs 7. - **Wave-front pulse (`ut_visuals.wavefront`) parked beside a label**: the front arc's half-width is 1.8 × amp, so an echo with amp 0.42 left at the probe face reaches 0.76 sideways and touches a tag placed `next_to` the probe/couplant (0.04 gap); the checker misses arcs inside the Wavefront group · spot: the last frame of each pulse travel — arc tips vs the nearest tag · fix: amp ≤ 0.3 near tags, or `FadeOut` the pulse on arrival · first seen ut_series_ep01 seg 4 end, round 3. - **Comparison drawn to true scale hides (or reverses) the spoken ordering**: "bigger crystal → narrower beam" cones drawn from the real crystal width over a short depth, so the 20 mm cone is wider than the 10 mm one at every drawn depth (smaller angle, wider beam); zones N / N–3N / far drawn to depth 3N + 2 mm leave the far field 0.2 units tall and the "far-field" flaw sits in the transition bracket · spot: measure the compared widths/heights on the end frame against the claim; check which bracket each example object sits in · fix: draw far-field cones from a virtual apex (half-width = depth·tanθ) or shrink the crystal scale; extend the depth (or a broken axis) so each zone gets room and put examples mid-zone · first seen ut_series_ep02 seg 4–5, review Q7.
- **"A inside B" drawn side by side**: "part and probe are in the water" with the water a band above the part (the part sits under it, dry) · spot: on the frame of the sentence, does the container enclose every object named in it? · fix: size the container from the enclosed group (`SurroundingRectangle(VGroup(part, probe), buff=0.15)`, z-index behind) · first seen ut_series_ep02 seg 3 (immersion panel). - **Contrast case drawn missing its target**: "planar flaws may not reflect the vertical beam" shown by a vertical dashed line that passes beside the crack, so it reads "the beam misses it" · fix: the contrast ray must hit the flaw and show its echo leaving sideways; the good case should meet the flaw face near-normal · first seen ut_series_ep02 seg 3 (angle panel). - **Self-driving updater left on through `self.clear()`**: a helper whose `advance(dt)` re-sets `stroke opacity=1` every frame (ScatterLane `_curve`) ignores the clear's fade — the waves stay bright while everything else fades, then pop off · spot: a 3 s frame inside a clear where one element is at full strength · fix: `m.clear_updaters()` before `self.clear()` · first seen ut_series_ep01 review Q3 (5:30), round 3.

- **No-op pointer: `Indicate(mob, color=<mob's own colour>, scale_factor=1.0)`**: nothing changes on screen, so the sentence it was meant to mark ("the difference in transmitted radiation…") gets no pointer · spot: grep `Indicate(` calls whose `color` equals the target's colour role (RAY_C on rays) and scale 1.0; the frame in the cue window equals the frame before · fix: a contrasting colour (INK/SRC_C) or `set_stroke(opacity=1)` → back, or `Circumscribe` each marked part · first seen rt_intro_principle seg 2 (round 1 of the layout-fix pass).
