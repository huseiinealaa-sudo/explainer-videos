# video-critic memory

Recurring faults in this repository. Each line: what it looks like · how to spot it · usual fix · first seen.
Look for every one of them in each preview. Keep this file under 150 lines; merge, don't repeat.

## Drawing and colour
- **Manim subclass default colours escape `VMobject.set_default(color=INK)`**: `Rectangle`/`Square` without `color=` get WHITE (invisible on the white board, only a PANEL_FILL smudge shows), `Circle` gets manim RED (reads as the alarm accent), `Polygon`/`Triangle` get manim BLUE #58C4DD (off-palette); `DashedVMobject(src, color=...)` ignores `color=` and copies `src`'s style, so a dashed WHITE outline is invisible **and cuts the black lines it crosses** · spot: a part with no outline, salmon-red small circles, light-cyan shapes, a short gap in a black line where nothing is visible · fix: pass `color=` (INK / GREY_INK / palette role) to every Rectangle, Circle, Polygon and to the *source* of a DashedVMobject; delete decorative shapes that are not named · first seen svp_winsfc_full seg 2.
- **Mechanism only pulsed, not moved**: the narration describes a motion or cause ("X cuts the beam of Y", "A pulls B", "moves with") but the frame only gets `Indicate`/`Flash` on a static `labeled_diagram` · spot: the same drawing, unchanged in every 3 s frame while such a sentence is spoken · fix: animate it (shift the linked VGroup, draw the beam/signal, flash the sensor), then return; root Quality standard: every mechanism is an animated drawing · first seen svp_winsfc_full seg 2. Worse form: nothing moves at all, only a label/arrow ("moves with the liquid", "pushes the piston ahead") · seen again prover_ep03_components seg 4 (return the part before later objects built at its rest coordinates are used).
- **Subject of the segment drawn tiny**: the part discussed for most of the segment sits in one or two cells while a part named once takes half the frame · spot: small parts (r < 0.1, < 0.6 units) under long narration · fix: enlarge those parts or zoom on them once the first callouts are done; `SyncedScene` is a plain Scene (no camera zoom), so use a scaled-copy inset (`VGroup(parts).copy().scale(2.5)`) in an empty region and fade it before that region is used · first seen svp_winsfc_full seg 2; again prover_ep03_components seg 4 (piston + poppet in part of C3, A2–B5 empty).
- **Part introduced in a later operating state**: a valve/piston first appears already open/moved (hole, offset), so the drawing contradicts the naming sentence ("inside the piston" while the open poppet sits outside it) and shows a state before it is explained · spot: compare the first frame of each new part with the words then · fix: introduce it at rest, animate into the state at the state's cue, keep the segment's end state · first seen prover_ep03_components seg 4.

- **Spoken motion animated to the value the tracker already has** (`lever.animate.set_value(0)` while lever is 0): the cue plays but nothing moves · spot: two identical frames across the cue of a motion verb · fix: put the part in the opposite state before the cue (end the previous segment there) · first seen pt_cal_ep02_pressure seg 4.
- **Stale `always_redraw` value on re-entry**: a redraw group removed by `clear()` and faded in again shows its old value (a readout 30.0 → jumps to 18.0) because updaters are suspended during FadeIn · fix: `for m in group: m.update()` before the FadeIn · first seen pt_cal_ep02_pressure seg 7. Variant: `redraw.animate.set_color(GOOD)` on an `always_redraw` is overwritten next frame (bar stays orange while "→ longer" is green) · fix: read the colour from a variable/tracker inside the lambda · pt_cal_ep05_verdict seg 5.
- **Function curve drawn `smooth=True` through a few table points wobbles** (√ curve with an S-bend near 15–25 %, a concave function drawn with an inflection) · spot: a kink or flat piece on a curve that should be monotone-concave/convex, on the frame after `Create` · fix: sample the data-module function at ≥ 50 points without smoothing (or `ParametricFunction`) and keep the table points only as dots · first seen pt_cal_ep05_verdict seg 4.
- **"Broken link" drawn by scaling the line to 0.01**: leaves a tiny red dot, the rest of the chain stays green, and once the red caption fades the chain looks intact · fix: two red stubs with a gap + small cross, and colour the downstream links/cards BAD and keep them · first seen pt_cal_ep05_verdict seg 5.
- **"Never use one X for A and B" drawn as two separate X's crossed out** → reads as the opposite rule · fix: draw ONE item carrying both (half grey/half blue hose, both icons) and cross that · first seen pt_cal_ep02_pressure seg 7.
- **Degenerate cross on a flat item**: a `cross(mob)` helper built from the bounding-box corners of a thin horizontal/vertical item (a hose, a line) collapses into one red line lying along it — reads as "red hose", not "forbidden" · spot: a red stroke on top of the item and no X on the frame after the cross cue · fix: cross a padded box (`cross(SurroundingRectangle(group_with_icons, buff=0.15))`) or give the helper a minimum height/width · first seen pt_cal_ep02_pressure seg 7, round 2.
- **Arrow grown from a stub loses its tip**: `Arrow` created 0.1 long then `put_start_and_end_on(...)` to full length shows as a plain line (no head), so a force/direction reads as a bar · fix: build the final Arrow and `GrowArrow` it, or `always_redraw(lambda: Arrow(..., tip_length=0.25))` on a ValueTracker · first seen pt_cal_ep02_pressure seg 8.
- **Same action in two palette roles**: opening a valve drawn red (danger) in one segment and orange (moving part) in another · spot: compare colours of the same part/action across segments · fix: one role per action, from the project CLAUDE.md · first seen pt_cal_ep02_pressure seg 5 vs 7.

## Callouts (labeled_diagram) and layout
- **Stacked callouts under parts that are close horizontally**: the lower label's leader arrow runs through the upper label's text · spot: a thin vertical "|" through a word; checker `text_over_shape` "Arrow from '<label>' to '<target>'" · fix: the lower arrow must fall outside the upper label's x-span (move the target part or use a target point farther right/left), or put labels on opposite sides; the checker's "move DOWN" suggestion often just swaps the crossing · first seen svp_winsfc_full seg 2 (callouts 4/5).
- **Callout centred on a target near the frame edge** → label inside the safe margin; and DOWN callouts from targets at different heights end up touching the neighbour label (the checker misses touching) · spot: `in_safe_margin`; a badge sitting on the last word of the next label · fix: two-line label text ("A\nB"), move the anchor 0.1–0.5 inward · first seen svp_winsfc_full seg 2 (callout 3).
- **Pointer to one of several named parts**: the label says plural / "each side" / "two ..." but the arrow hits one part · fix: `Indicate(VGroup(all parts))` at the cue, or target the common carrier · first seen svp_winsfc_full seg 2.
- **Sub-parts listed in speech bundled into one callout** ("block with wheels on two bars, carrying flag and ramp"): only the carrier is pointed at · fix: `Indicate` each sub-part at its own word (`self.c(s, word)`) · first seen svp_winsfc_full seg 2. Variant: two sub-parts drawn as the same marks under one label shown before the second name is spoken ("seals · Rulon riders") → draw each distinctly, one label + arrow at each word · prover_ep03_components seg 4. Again pt_cal_ep02_pressure seg 3 ("Handles + pump piston" arrow on the handle tip only).
- **Badge farther from its part than a neighbour's badge** (episode-wide fixed `badge_pos`, part drawn off-centre or moved) · spot: in the frame where the badge appears, compare its distance to its part and to the neighbour part · fix: place it with `next_to(part, DOWN, 0.15)` or `Indicate(part)` at the name cue · first seen prover_ep03_components seg 4 (badge 4 vs poppet).
- **Hand-placed label just above a drawing edge** (`move_to` at a fixed height, < 0.15 clear): descenders (g, p, q, y) touch a taller neighbour shape (flange, cap) · spot: checker `text_over_shape` with share_of_text < 0.01 at the text's bottom · fix: raise 0.15–0.2 or `next_to(shape, UP, buff=0.25)`; the checker's "UP by 0.05" leaves it touching · first seen prover_ep03_components seg 4.

- **Label at a fixed coordinate on the body of a drawing** ("weld 20 mm" on the plate, "Tungsten" across the plate edge) · spot: `text_over_shape` share_of_text > 0.5 · fix: `next_to(part, LEFT/RIGHT)` in free space, or move the part · first seen rt_intro_principle seg 2, seg 5.
- **Late white-filled inset/zoom ring at a fixed coordinate covers an earlier label** · spot: part of a word missing next to a circle added at the end of a segment · fix: reflow the older label (two lines, other side) or place the inset with `next_to` a free region · first seen rt_intro_principle seg 3.
- **Long one-line note stacked in a right-half column runs off the frame** (`next_to(group, DOWN)` + `align_to(LEFT)` at x > 1) · spot: `out_of_frame` RIGHT, text cut mid-word · fix: `fit(note, width)` or split lines before building the box · first seen rt_intro_principle seg 4. Variant: `mob.animate.next_to(point, DOWN)` centres a long line on the point and pushes it out LEFT (seg 5). Milder form the checker passes: a line `next_to(box, RIGHT)` ending 0.26 from the edge (pt_cal_ep02 seg 10) → shorten/split it.
- **always_redraw label beside a moving object collides with shapes added at its end position** (limit line / zone at the source height) · spot: finding only in the last seconds of a segment · fix: put the label on the side away from later shapes (UP) · first seen rt_intro_principle seg 5.
- **Label `next_to` a thin marker box on a strip lands on the strip** ("Ug" on the film) · fix: attach it to the existing label below (`next_to(l_pen, RIGHT)`) · first seen rt_intro_principle seg 4.

- **Layout fix creates a new collision with a text column that grows later** (a label moved with `next_to(part, LEFT)` lands on a later `next_to(prev, DOWN)` line) · spot: a new finding in round N+1 on the element that was fixed · fix: check the new box against every text added later in the segment; split long result lines in two · first seen rt_intro_principle seg 5, round 2.
- **Corner tag at a fixed coordinate crossed by a tracker-driven dimension arrow or guide** (source height changes with D) · spot: `text_over_shape` with a DashedLine/DoubleArrow at the tracker's extreme value · fix: attach the tag to the section heading (`next_to(self.sec, RIGHT)`), away from the rig's range of motion · first seen rt_intro_principle seg 5.
- **Late frame or link drawn up to a labelled group touches its labels**: `emphasize(film)` (buff 0.1) over labels placed `next_to(film, DOWN, 0.15)`, or a DashedLine to an inset ring's top ending on the label under the rim · spot: `text_near_shape` gap 0.03–0.05 only in a segment's last seconds · fix: emphasize the group including its labels (text inside its own frame is allowed); end links at `ring.point_at_angle(...)` on the side facing the source · first seen rt_intro_principle seg 2, seg 3. Variant: an inset's dashed link to a short hose runs through the neighbouring device body (checker ignores line-on-shape) · pt_cal_ep02_pressure seg 5.

- **`fit()` on a grid sized by its widest labels**: `arrange_in_grid` gives each column the width of its longest name, so a 7-column grid overflows SAFE_WIDTH, `fit` shrinks it, the grid fills only the upper half (rows 5–6 empty), icons and names get small and column gaps are uneven; the same happens to a one-row group with long names (bubbles) · spot: blank lower 40 % on a catalogue/grid page, pages of the same kind drawn at different scales · fix: fewer columns (5×5 for 25 items), larger `size`, two-line names, and centre the grid vertically (`move_to(DOWN*0.3)`) · first seen symbol_gallery seg 2.

- **Value readout in a fixed-size box touches the box once the number grows** ("0.0 bar" fits, "18.0 bar" fills the box edge to edge); the checker exempts text inside its own frame, so it reports 0 · spot: every frame where a live readout has 3+ digits · fix: size the box from the widest value the scene reaches, or `fit(text, box.width - 0.25)` in the redraw · first seen pt_cal_ep02_pressure seg 4–7. Same blind spot for a fixed-width "paper"/list frame whose longest row ("reference + cert. expiry") ends on the right border, and for column headers placed at fixed offsets in a small box ("As-FoundAs-Left" crossing the left edge) · fix: build the frame with `SurroundingRectangle(content, buff=0.3)`, `arrange(RIGHT, buff=0.4)` the headers · pt_cal_ep05_verdict seg 2, seg 5.
- **Callout for a port/connection lands on the device it feeds** ("Top port: EXT" arrow on the module's top edge, not the riser pipe) · spot: follow the arrow tip on the frame of the cue · fix: target the pipe/port itself or `Indicate(port)` at the word · first seen pt_cal_ep02_pressure seg 3, round 3.
- **Generic transmitter drawn with `bubble=False` and no tag reads as a person** (round head on a box body with a stub arm); in a hazardous-area scene it "walks" to the workshop like a technician · spot: an unlabelled head-and-body figure in a loop drawing · fix: `transmitter(bubble=True)` or `tag("PT-101", ...).next_to(xm, UP)` · first seen pt_cal_ep01_device seg 3, seg 8.
- **Wire routed via a corner inside a box**: `pipe(a, [x_a, box_y], box.get_left())` with `x_a` just right of the box's left edge → the wire enters through the top edge and runs inside the box 0.05–0.1 from its label (checker exempts text in its own frame) · spot: a vertical line crossing a box's top edge next to the first letter of its label · fix: end the wire on `box.get_top()` or move the source ≥ 0.3 outside the box's x-span · first seen pt_cal_ep01_device seg 3.
- **Feature placed at a fixed offset from a case lands on an inner part** (PX port `case.get_right() + LEFT*0.35 + UP*1.2` sits on the screen corner), and a pointer aimed at `group.get_right()` hits the neighbour placed `next_to(group, RIGHT)` (internal-ports arrow tip on the baro opening) · fix: place ports on the case edge (`next_to(case, RIGHT/UP, buff=0)`), aim arrows at a member (`ports[-1].get_top()`) · first seen pt_cal_ep01_device seg 5.
- **Heading and list of opposite polarity**: a red "X loses:" heading over green "Accept: ..." lines reads as a contradiction · fix: one polarity per block (red list of what is lost, then a separate green "with Accept:" block/drawing) · first seen pt_cal_ep01_device seg 7.
- **Selector/switch drawn as a static pill with both positions and no state** ("pressure | vacuum") while speech names a switch · fix: a knob/highlight on one word that moves to the other at the cue · first seen pt_cal_ep02_pressure seg 9.
- **Two texts packed inside one pill/box run together** ("pressure|vacuum" selector, words touching each other and the pill); checker misses it (same group / own frame) · fix: `arrange(RIGHT, buff=0.3)` the words, then size the pill with `SurroundingRectangle(..., buff=0.15)` · first seen pt_cal_ep02_pressure seg 9.
- **Chart labels placed on the same fixed row** (`move_to([0, y]).align_to(x)`) for successive curve parts grow into each other ("fine adjust, from below|small sag…") · fix: `next_to(previous_label, RIGHT, buff=0.4)` or alternate rows / attach each to its curve piece · first seen pt_cal_ep02_pressure seg 6.

- **Storyboard text-share figure understated** (5 % claimed; cards, text-only decision tree and a process_flow with text tags ≈ 40 %) · recount from the 3 s frames every full run · first seen pt_cal_ep06_trim (still ≈ 40 % in round 2: mini gauges beside a text tree do not turn it into a drawing). ## Symbols and P&ID drawings
- **Thin stroke inside a process path**: a symbol's own nozzle (pump discharge, tank outlet) is drawn at the thin symbol stroke, so the heavy process line has a thin piece that reads as another line type once a line legend is on screen · spot: follow the process path end to end on the loop frame · fix: draw the nozzle at `PROCESS_STROKE` or keep it ≤ 0.15 long and start the process line at the casing · first seen symbol_gallery seg 9.
- **Tag style mixed in one loop** (FV-101 with its loop number, "(FE)" without) · fix: tag every element of the loop the same way from the data module · first seen symbol_gallery seg 9.

## Captions (`self.say`)
- **Number typed in a caption, not from the data module** (a "standard" value such as 4–20 mA) · spot: grep the script's `say(` strings for digits · fix: move it to `<name>_data.py` and cite it in the sources file · first seen symbol_gallery seg 9.
- **Caption names an element that is not drawn yet** (caption set before the `play` that creates it; line runs to an empty spot for 2 s) · fix: `say` after the element's `Create`, or create the target with the line · first seen symbol_gallery seg 9.
- **Stale caption**: a caption stays 20–30 s while the narration moves on to other parts · spot: identical bottom line across 6+ consecutive frames whose callouts change · fix: replace or clear it at the next sentence cue · first seen svp_winsfc_full seg 2. Variant: a closing recap (process_flow) shown under the last segment's section heading ("Automatic generation") · fix: `section_title(self, "Recap", prev=self.sec)` before it · pt_cal_ep02_pressure end. Variant: a state label kept after the animation that removes the state (red "same offset in every point" over dots already zeroed) · fix: `Transform` it to the new state ("offset removed", GOOD) in the same play · pt_cal_ep01_device seg 6.
- **Bare number on a caption** (e.g. "±0.0005%") with no quantity name · fix: name it ("repeatability ±0.0005 %"), split long captions into two at their own cues · first seen svp_winsfc_full seg 2.
- **Ambiguous caption wording that contradicts an earlier segment** (e.g. "both ways" after "unidirectional") · spot: read captions against earlier segment titles/captions · fix: reword to the source's claim · first seen svp_winsfc_full seg 2.

## Review workflow notes
- Clock of a word = `start` of the segment's overlap report + `words[].start` from `tmp/<script>/audio/seg{k}.json`.
- Preview frames are 854×480: 60.05 px per unit, centre (427, 240); grid columns ≈142 px, rows 80 px. Unit x = px/60.05 − 7.11, y = (240 − px)/60.05.
- A segment run can leave an extra `overlap/segNN.json` for the next segment (not listed in `qa_summary.json`, window after the preview end): ignore it.
- Older projects have no storyboard: say so and use the segment table in `projects/<name>/CLAUDE.md`.
- `labeled_diagram` places each label centred on the target, 0.8 beyond the tip, along the direction; target = Mobject → tip on its edge; there is no buff/offset argument, so fixes are target/direction/text changes.
- Older prover scripts define a local text-position `cue()` (not word timings): check each cue against the word clock (prover_ep03 seg 4: within ±0.3 s, acceptable).
- The checker keeps a Text's original name after `Transform(state, new_text)`: a finding's `until` can run past the text change; check a frame after the transform before confirming the whole window.
- **Checker blind spots**: radial Line bursts touching a text, and a `dim_line` label touching the part on the side it faces · look at every label next to a burst or a dimension line · fix: shift the tags, or `side=LEFT` / outer side · first seen rt_intro_principle seg 3, seg 4.
- **Silent videos** (NARRATION = durations, no word timings): judge drawing–name fit (each drawing vs its name and the documented form, e.g. `explainer/symbols/SOURCES.md`), use the bottom captions as the "speech", and time events with `at(s, fraction)` = segment start + fraction × duration from the script · first seen symbol_gallery.
- Ghosted or half-drawn text on a 3 s frame (FadeIn/Write in progress, e.g. rt_intro_principle 0:21, 0:48, 3:51) is not an overlap: check the next frame before confirming.
